  <section id="problem" class="study-section">
    <span class="eyebrow">01 / PROBLEM STATEMENT</span>
    <h2>When Does a Photograph Improve Category Prediction over a Descriptive Title?</h2>
    <p>E-commerce catalogs link multiple modalities for each product listing: descriptive text (titles, bullet points, specifications) and photographic imagery (primary studio shots, contextual lifestyle photos). While text often contains explicit category keywords, it can suffer from promotional noise, ambiguous terms, or keyword stuffing. Conversely, photographs capture physical geometry, materials, and silhouettes, but may struggle with fine-grained distinctions without context (e.g., differentiating a full dining <code>CHAIR</code> from a low <code>STOOL_SEATING</code>, or a ceiling <code>LIGHT_FIXTURE</code> from a freestanding <code>LAMP</code>).</p>
    
    <p>Formally, given a paired input sample $(x_{\text{img}}, x_{\text{txt}})$ containing an RGB catalog image $x_{\text{img}}$ and an English listing title $x_{\text{txt}}$ belonging to the same product listing, a model predicts a discrete categorical label $\widehat{y} \in \{0, \dots, 9\}$ across <strong>ten mutually exclusive e-commerce product categories</strong>.</p>

    <p>This study investigates three primary research questions:</p>

    <div class="highlight-stat-row">
      <div class="highlight-stat-card">
        <div class="num">Q1</div>
        <div class="label">Cross-Modal Synergy (M2 Verified)</div>
        <div class="desc">Does combining visual and textual representations improve product classification over the strongest unimodal baseline under strictly masked titles? <em>(Verified in M2: Concat improves Macro-F1 by +3.69 pp across all seeds).</em></div>
      </div>
      <div class="highlight-stat-card">
        <div class="num">Q2</div>
        <div class="label">Interaction vs. Concat (M3 Planned)</div>
        <div class="desc">Does elementwise multiplicative interaction ($v \odot t$) capture richer cross-modal relationships than simple linear feature concatenation ($[v, t]$)?</div>
      </div>
      <div class="highlight-stat-card">
        <div class="num">Q3</div>
        <div class="label">Parameter-Matched Control (M3 Planned)</div>
        <div class="desc">When holding trainable classifier capacity exactly equal (214,666 parameters), does the multiplicative product outperform an elementwise additive mean baseline?</div>
      </div>
    </div>
  </section>

    <h2>Amazon Berkeley Objects (ABO): Provenance, Filtering, and Class Support</h2>
    <p>Amazon Berkeley Objects (ABO) is a large-scale multimodal dataset introduced by Collins et al. (CVPR 2022). The full release contains 147,702 product listings and 398,212 catalog images. To ensure computational tractability while adhering to course depth requirements, our study uses the small-image package (longest edge bounded at 256 pixels) and the primary product metadata under the Creative Commons Attribution 4.0 International license (CC BY 4.0).</p>

    <h3>Metadata Audit &amp; Pair Ingestion Pipeline</h3>
    <p>A rigorous metadata audit screened the raw catalog to build the frozen cohort:</p>
    <ul>
      <li><strong>Initial Ingestion:</strong> Evaluated 19,616 Amazon.com listings. Exactly 19,542 listings possessed a non-empty <code>en_US</code> title, a valid single catalog category, and an indexed primary image reference (74 listings lacked an image match, a 0.38% omission rate).</li>
      <li><strong>Conflict Resolution:</strong> The retained listings mapped to 16,605 unique image IDs. Exactly 387 image IDs were associated with conflicting product type labels across duplicate listings and were discarded. For non-conflicting duplicate image IDs, the lexicographically smallest listing ID was retained, leaving 7,221 candidate pairs.</li>
      <li><strong>Pair Review &amp; Filtering:</strong> Manual review of the 7,221 candidate pairs excluded exactly <strong>5 listings</strong> (an acceptance rate of 99.93%):
        <ul>
          <li><code>B0777Z915W</code>: Excluded due to German title text in the <code>en_US</code> catalog field.</li>
          <li><code>B0759Z13XN</code> (ottoman), <code>B07B4M93BC</code> (loveseat), <code>B0778X4L9J</code> (fabric swatch), <code>B07F2G6417</code> (TV media cabinet): Excluded due to out-of-scope taxonomy.</li>
        </ul>
      </li>
      <li><strong>Final Curated Cohort:</strong> Exactly <strong>7,216 verified, aligned image–title pairs</strong> across ten categories.</li>
    </ul>

    <h3>Title Lexical Masking Policy &amp; Bias Mitigation</h3>
    <p>In e-commerce listings, titles frequently include explicit class names (e.g., <em>"Contemporary Leather Executive Office Chair"</em>). Without intervention, a text classifier can solve the task via trivial string matching without learning semantic representations. To prevent shortcut learning, we enforce an exact class-name masking policy across all splits:</p>
    <ul>
      <li><strong>Masking Rule:</strong> Matches to canonical category names and plurals are replaced with <code>[MASK]</code>, regardless of the true label.</li>
      <li><strong>Cohort Impact:</strong> Exactly <strong>3,334 of 7,216 titles (46.20%)</strong> were modified by the mask.</li>
      <li><strong>Category Variation:</strong> Masking heavily affects categories with ubiquitous title keywords (<code>RUG</code>: 99.3%, <code>LAMP</code>: 98.6%, <code>TABLE</code>: 85.0%), while categories with brand-dominated or itemized titles are rarely masked (<code>GROCERY</code>: 0.1%, <code>STOOL_SEATING</code>: 3.1%).</li>
    </ul>

  <section id="leakage" class="study-section">
    <span class="eyebrow">03 / LEAKAGE DEFENSE &amp; SPLIT PROTOCOL</span>
    <h2>Product-Group Disjoint Partitioning: Zero Entity Leakage</h2>
    <p>In e-commerce catalogs, multiple listings often belong to the same parent product (e.g., color variants, dimension options, or identical pack sizes sharing stock photos). Random naive row partitioning would leak near-identical images and titles across train and test sets, artificially inflating benchmark metrics.</p>

    <p>To eliminate entity contamination, we enforce <strong>Product-Group Disjoint Partitioning using split seed 36</strong>:</p>
    <ul>
      <li><strong>Partition Unit (<code>group_id</code>):</strong> Product groupings cluster near-identical perceptual image hashes, identical stock photographs, and shared parent brand/model codes. Across the 7,216 listings, there are exactly <strong>5,281 distinct product groups</strong> (4,333 singletons and 948 multi-listing groups up to 24 items).</li>
      <li><strong>Disjoint Invariant:</strong> Zero product groups are shared across partitions ($\text{Train} \cap \text{Val} = \emptyset$, $\text{Train} \cap \text{Test} = \emptyset$, $\text{Val} \cap \text{Test} = \emptyset$).</li>
      <li><strong>Target Proportions:</strong> The deterministic allocation partitions listings into ~70% Train, ~15% Validation, and ~15% Test while guaranteeing representation for all 10 classes in every split.</li>
    </ul>

  <section id="methodology" class="study-section">
    <span class="eyebrow">04 / METHODOLOGY &amp; MODALITY ENCODERS</span>
    <h2>Modality-Specific Encoders, Preprocessing &amp; Feature Caching</h2>
    <p>Following established multimodal benchmarking protocol, feature extraction leverages high-quality pretrained frozen backbones, isolating the investigation to <strong>fusion operations, cross-modal interaction, and representation alignment</strong>.</p>

    <figure class="study-figure" style="margin: 24px 0;">
      <img src="{{ '/assets/a3/fig3_1_pipeline_architecture.png' | relative_url }}" alt="A3 Multimodal Pipeline Architecture" style="max-width: 100%; border-radius: 8px; border: 1px solid var(--line);">
      <figcaption style="margin-top: 8px; font-size: 13px; color: var(--muted); text-align: center;">Figure 3.1: Two frozen encoders extract feature caches indexed by listing ID. Head training uses cross-entropy, validation selects checkpoints, and the locked suite evaluates held-out test predictions.</figcaption>
    </figure>

    <div class="study-two-col">
      <div>
        <h3>1. Visual Modality: ResNet-18</h3>
        <ul>
          <li><strong>Architecture:</strong> Deep Residual Network with 18 layers (He et al., 2016), loaded from <code>torchvision.models.resnet18(weights=ResNet18_Weights.IMAGENET1K_V1)</code>.</li>
          <li><strong>Preprocessing:</strong> EXIF orientation correction, RGB conversion, shortest edge resized to $256 \text{ px}$, center crop to $224 \times 224$, and ImageNet channel normalization.</li>
          <li><strong>Representation:</strong> Global average pooling exports a fixed <strong>512-dimensional feature vector</strong> $f_i \in \mathbb{R}^{512}$.</li>
          <li><strong>Frozen Backbone:</strong> All convolutional weights remain 100% frozen; zero gradients into the backbone. Extraction time: 384.41s for 7,216 images on CPU.</li>
        </ul>
      </div>
      <div>
        <h3>2. Textual Modality: DistilBERT</h3>
        <ul>
          <li><strong>Architecture:</strong> DistilBERT Transformer (Sanh et al., 2019), loaded from HuggingFace <code>distilbert-base-uncased</code> (revision <code>12040acc</code>).</li>
          <li><strong>Preprocessing:</strong> Unicode NFKC normalization, whitespace collapse, exact class-name masking, and WordPiece tokenization capped at <strong>64 tokens</strong>.</li>
          <li><strong>Representation:</strong> The 768-dimensional hidden state of the first special token (<code>[CLS]</code>) is extracted: $f_t \in \mathbb{R}^{768}$. Median sequence length is 22 tokens (Max 53 tokens; zero sequences truncated).</li>
          <li><strong>Frozen Backbone:</strong> Transformer layers remain 100% frozen. Extraction time: 297.02s for 7,216 titles on CPU.</li>
        </ul>
      </div>
    </div>

    <h3>Trainable Projection Layers &amp; Latent Alignment</h3>
    <p>To align the heterogeneous feature spaces ($512\text{D}$ image vs. $768\text{D}$ text) prior to fusion, independent linear projection layers map both modalities into a shared $128\text{D}$ latent space with ReLU activations:</p>
    $$u = \operatorname{ReLU}(W_i f_i + b_i) \in \mathbb{R}^{128}, \quad W_i \in \mathbb{R}^{128 \times 512}$$
    $$v = \operatorname{ReLU}(W_t f_t + b_t) \in \mathbb{R}^{128}, \quad W_t \in \mathbb{R}^{128 \times 768}$$
  </section>
