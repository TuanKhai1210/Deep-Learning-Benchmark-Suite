  <section class="study-section" id="data">
    <span class="eyebrow">01 / DATASET</span><h2>Material labels.<br>Real underwater variability.</h2>
    <p>TrashCan 1.0 Material contains RGB underwater frames with COCO object polygons. Retain all 16 foreground categories, including ROV and biological classes, and add background for <strong>17 output classes</strong>. The eight trash categories include materials, fishing gear and a miscellaneous category.</p>
    <div class="data-stat-grid"><div><strong>7,212</strong><span>Readable annotated images</span></div><div><strong>12,336</strong><span>Object annotations</span></div><div><strong>312</strong><span>Filename-derived video groups</span></div></div>
    <p class="small-note">Counts are measured preliminary EDA, not model results. Video groups are inferred from filename prefixes; they do not establish independence between different videos from the same dive.</p>
    <p>Class imbalance is substantial: <code>trash_plastic</code> has <strong>1,864</strong> objects, while <code>trash_rubber</code> has <strong>142</strong> and occurs in only seven video groups.</p>
    <p><a class="text-link" href="https://irvlab.cs.umn.edu/resources/trashcan">Official dataset source ↗</a> <a class="text-link" href="https://github.com/TuanKhai1210/Deep-Learning-Benchmark-Suite/tree/main/reports/a2/evidence">Measured EDA summaries ↗</a></p>
    <p class="small-note">Dataset authors: Jungseok Hong, Michael Fulton and Junaed Sattar; imagery: JAMSTEC. Retain the supplied license and annotation license records. Academic/research use does not imply unrestricted commercial use or redistribution. Raw data and checkpoints stay outside this repository.</p>
  </section>

  <section class="study-section" id="split">
    <span class="eyebrow">02 / LEAKAGE PREVENTION</span><h2>Hold out videos,<br>not neighboring frames.</h2>
    <div class="study-two-col"><div><h3>Original split: 127 shared groups</h3><p>The original 6,008/1,204 image partitions share <strong>127 video groups</strong>. Keep the original notebook and EDA outputs as evidence of this finding; do not use that partition for the main video-holdout comparison.</p></div><div><h3>New split: zero video-group overlap</h3><p>Pool the source metadata and assign whole video groups using <strong>split seed 36</strong>, targeting approximately 70/15/15 by image count. Every image belongs to exactly one new partition; no model predictions or scores were used to construct the split.</p></div></div>
    <div class="table-scroll"><table class="data-table"><caption>Frozen seed-36 video-disjoint split</caption><thead><tr><th scope="col">Partition</th><th scope="col">Images</th><th scope="col">Video groups</th><th scope="col">Annotations</th></tr></thead><tbody><tr><td>Train</td><td>5,057</td><td>207</td><td>8,563</td></tr><tr><td>Validation</td><td>1,077</td><td>54</td><td>1,956</td></tr><tr><td>Test</td><td>1,078</td><td>51</td><td>1,817</td></tr></tbody></table></div>
    <p class="small-note">Each foreground class has at least three train videos and two videos in each held-out partition. Rare-class support is still small, limiting generalization claims. The full manifest is in the accompanying EDA bundle: <code>eda_v1/splits/trashcan_material_seed36_v1.json</code>.</p>

  <section class="study-section" id="methods">
    <span class="eyebrow">03 / PROPOSED METHODS</span><h2>One baseline.<br>One transferred system.<br>One controlled change.</h2>
    <div class="future-grid">
      <article class="future-card"><span class="eyebrow">BASELINE / SCRATCH</span><h2>Lightweight U-Net</h2><p>A four-stage convolutional segmentation baseline, initialized from scratch. Proposed loss: cross-entropy plus soft Dice, excluding ignore pixels.</p></article>
      <article class="future-card"><span class="eyebrow">MODERN / PRETRAINED</span><h2>SegFormer-B0</h2><p>Fine-tune the ADE20K checkpoint with a new 17-class head. ImageNet-1k encoder pretraining followed by ADE20K fine-tuning supplies the initial weights.</p></article>
      <article class="future-card"><span class="eyebrow">CONTROLLED EXPERIMENT</span><h2>Color augmentation</h2><p>Compare SegFormer with color jitter on versus off. Train-only probability 0.5; brightness, contrast and saturation factors [0.9, 1.1]; hue shift [-0.01, 0.01]. Masks remain unchanged.</p></article>
    </div>
    <p>U-Net versus SegFormer changes both architecture and pretraining: it is a <strong>system comparison</strong>, not a causal isolation of transfer learning. The color-augmentation comparison keeps split, weights, geometry, optimization, loss, budget and run seed fixed.</p>
    <p>Initial run seed: <code>69420</code>. Paired repetitions at <code>67</code> and <code>69</code> are optional and depend on compute; none are completed experiments.</p>
  </section>

  <section class="study-section" id="evaluation">
    <span class="eyebrow">04 / EVALUATION PROTOCOL</span><h2>Foreground quality.<br>Class-level evidence.</h2>
    <div class="study-two-col"><div><h3>Targets &amp; preprocessing</h3><p>Rasterize native polygons with the versioned Pillow 12.3.0 converter. Same-class polygons are unioned; cross-class overlap receives <code>255</code>. Preserve aspect ratio on a <strong>512 × 512</strong> letterbox canvas; RGB uses bilinear resizing, targets use nearest-neighbor and padding is ignored.</p><p>Color jitter operates before padding and normalization. Validation and test preprocessing is deterministic; learned statistics use training data only.</p></div><div><h3>Metrics &amp; checkpoint selection</h3><p>Primary metric: <strong>macro mIoU over 16 foreground classes</strong>. Report foreground Dice, trash-only mIoU (IDs 9–16), per-class IoU/Dice and support, background-inclusive scores and ignore coverage.</p><p>Choose the highest validation foreground mIoU; resolve ties with lower validation loss, then the earlier epoch. Lock choices before test evaluation. Instance mask AP and box AP are not semantic metrics.</p></div></div>
    <p>Prospective augmentation decision: validation trash-only mIoU improves by at least <strong>0.01 absolute</strong>, with overall foreground mIoU and Dice each declining by no more than 0.01.</p>
    <p class="small-note">Provisional compute plan: batch size 4, up to 40 epochs, patience 8, one 12–16 GB GPU and an estimated 12–24 GPU-hours for three configurations at one seed. A post-approval pilot must confirm feasibility and freeze optimizer, schedule, loss weights and budget.</p>
  </section>
