    <span class="eyebrow">01 / PROBLEM AND DATA DESCRIPTION</span>
    <h2>Small images. Meaningful differences.</h2>
    <div class="study-two-col">
      <div><p>Fashion-MNIST is the main dataset for a ten-class clothing-image classification task. Each model receives the same 28 × 28 grayscale image; the architecture determines how it represents that image.</p><p>The data pipeline will record provenance and dependency versions, explore class balance and representative samples, and verify that the subsets do not overlap.</p></div>
      <div><h3>One split, shared by everyone.</h3><p>The proposed stratified split uses seed <code>36</code>. Saved indices and a recorded checksum will identify the exact split. The official test set stays untouched; it is not used for tuning.</p></div>
    </div>
    <div class="data-stat-grid"><div><strong>50,000</strong><span>Proposed training samples</span></div><div><strong>10,000</strong><span>Proposed validation samples</span></div><div><strong>10,000</strong><span>Official test samples</span></div></div>
    <p class="small-note">Split counts are a proposal, not a claim of completed preparation. Normalization statistics must be measured on the training subset only.</p>
  </section>
  <section id="method" class="study-section">
    <span class="eyebrow">02 / METHODOLOGY</span>
    <h2>Same task. Five ways to see it.</h2>
    <p>Every model accepts <code>[B, 1, 28, 28]</code> and returns raw logits <code>[B, 10]</code>. Flattening, sequence construction and patch tokenization belong inside the model, keeping the external training interface consistent.</p>
    <details id="model-linear" class="model-detail" open><summary><span><span class="eyebrow">01</span>Linear classifier</span></summary><p>A flattened-image baseline that exposes how far a linear decision boundary can go. Owner: Nguyễn Hạo Thiên. Compare its limitations with the nonlinear MLP and spatial CNN.</p></details>
    <details id="model-mlp" class="model-detail"><summary><span><span class="eyebrow">02</span>Multilayer perceptron</span></summary><p>A nonlinear model over flattened pixels. Owner: Nguyễn Anh Khoa. Record depth, widths and activation choices; analyze the consequences of not explicitly preserving local spatial structure.</p></details>
    <details id="model-cnn" class="model-detail"><summary><span><span class="eyebrow">03</span>Custom convolutional network</span></summary><p>A self-designed CNN that uses local receptive fields and weight sharing. Owner: Nguyễn Hạo Thiên. Document convolution and pooling choices and investigate the errors that remain.</p></details>
    <details id="model-rnn" class="model-detail"><summary><span><span class="eyebrow">04</span>Recurrent model · LSTM or GRU</span></summary><p>A sequence representation of an image. Owner: Nguyễn Anh Khoa. The recurrent cell and row, column or patch sequence remain to be frozen; report their effect on order sensitivity and information aggregation.</p></details>
    <details id="model-transformer" class="model-detail"><summary><span><span class="eyebrow">05</span>Transformer</span></summary><p>A token-based representation with self-attention. Owner: Tạ Tuấn Khải. Specify patch construction, positional encoding and classification aggregation; examine the trade-off between global interactions and compute.</p></details>
    <div class="table-scroll" role="region" aria-label="Shared experiment policy" tabindex="0"><table class="data-table"><thead><tr><th scope="col">Decision</th><th scope="col">Policy / current status</th></tr></thead><tbody>
      <tr><td>Split seed</td><td><code>36</code> · generates one shared train/validation partition.</td></tr>
      <tr><td>Training seeds</td><td><code>69420</code>, <code>67</code>, <code>69</code> · reinitialize for each run. Five families × three seeds = 15 planned main runs.</td></tr>
      <tr><td>Quantitative evaluation</td><td>Accuracy and macro-F1; per-seed scores plus mean and standard deviation. Also report parameters, training time and inference time under a documented procedure.</td></tr>
      <tr><td>Checkpoint selection</td><td>Proposed: highest validation macro-F1; ties use lower validation loss, then earlier epoch. No test-based selection.</td></tr>
      <tr><td>Still to freeze</td><td>Normalization, augmentation, batch size, epoch and tuning budgets, early stopping, hardware and timing procedure.</td></tr>
    </tbody></table></div>
