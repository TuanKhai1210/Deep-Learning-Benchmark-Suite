  <section id="problem" class="study-section"><span class="eyebrow">ASSIGNMENT 3 / PROBLEM STATEMENT</span><h2>Make a multimodal decision evidence-based.</h2><p>The final task, modalities, prediction target, and evaluation question are pending instructor and proposal confirmation. Before implementation, the team will state the input modalities, missing-data policy, class structure, and expected benefit of fusion in a frozen experiment contract.</p></section>

  <section id="data" class="study-section"><span class="eyebrow">02 / DATASET DESCRIPTION &amp; EDA</span><h2>Provenance before model choice.</h2><p>No dataset or EDA is claimed yet. Selection must confirm task relevance, legal access, license, modality alignment, split independence, class support, missing values, leakage risk, and reproducible download or acquisition instructions.</p></section>

  <section id="method" class="study-section"><span class="eyebrow">03 / METHODOLOGY</span><h2>Single-modality baselines and fusion.</h2><p>Methodology will include unimodal baselines, compatible alignment and preprocessing, a defined fusion model, and ablations that isolate whether additional modalities improve the task. The chosen architectures and components will be documented only after proposal approval.</p></section>

  <section id="setup" class="study-section"><span class="eyebrow">04 / EXPERIMENTAL SETUP</span><h2>One protocol for every condition.</h2><p>Planned setup covers dataset splits, seeds, preprocessing fit on training data, batching, optimization, checkpoint selection, repeated runs, hardware, metrics, and fair comparison against unimodal baselines. No numbers are reported until corresponding repository runs exist.</p></section>

  <section id="results" class="study-section"><span class="eyebrow">05 / RESULTS</span><h2>Results will follow verified artifacts.</h2><div class="result-placeholder"><span class="status-tag">NOT STARTED</span><h3>No experimental results claimed.</h3><p>Report tables, curves, ablations, and checkpoints will be linked only after the proposal, implementation, and official evaluation are complete.</p></div></section>

  <section id="discussion" class="study-section"><span class="eyebrow">06 / COMPARISON, DISCUSSION &amp; ERROR ANALYSIS</span><h2>Test the value of each modality.</h2><p>The future analysis will compare unimodal and multimodal systems under matched splits and seeds, examine modality agreement and disagreement, and inspect failures where one or both modalities are weak, missing, noisy, or misleading.</p></section>

  <section id="limitations" class="study-section"><span class="eyebrow">07 / LIMITATIONS &amp; CONCLUSION</span><h2>Publish uncertainty explicitly.</h2><p>Dataset and modality limitations, alignment assumptions, access restrictions, missing-data effects, and compute scope will be stated in the final conclusion.
