  <section id="problem" class="study-section">
    <span class="eyebrow">01 / PROBLEM STATEMENT</span>
    <h2>When Does a Photograph Improve Category Prediction over a Descriptive Title?</h2>
    <p>E-commerce catalogs link multiple modalities for each product listing: descriptive text (titles, bullet points, specifications) and photographic imagery (primary studio shots, contextual lifestyle photos). While text often contains explicit category keywords, it can suffer from promotional noise, ambiguous terms, or keyword stuffing. Conversely, photographs capture physical geometry, materials, and silhouettes, but may struggle with fine-grained distinctions without context (e.g., differentiating a full dining <code>CHAIR</code> from a low <code>STOOL_SEATING</code>, or a ceiling <code>LIGHT_FIXTURE</code> from a freestanding <code>LAMP</code>).</p>
    
    <p>Formally, given a paired input sample $(x_{\text{img}}, x_{\text{txt}})$ containing an RGB catalog image $x_{\text{img}}$ and an English listing title $x_{\text{txt}}$ belonging to the same product listing, a model predicts a discrete categorical label $\widehat{y} \in \{0, \dots, 9\}$ across <strong>ten mutually exclusive e-commerce product categories</strong>.</p>

    <p>This study investigates three primary research questions:</p>

    <div class="highlight-stat-row">
      <div class="highlight-stat-card">
        <div class="num">Q1</div>
        <div class="label">Cross-Modal Synergy</div>
        <div class="desc">How much predictive gain does combining visual and textual features provide over individual unimodal baselines under a strictly enforced title-masking protocol?</div>
      </div>
      <div class="highlight-stat-card">
        <div class="num">Q2</div>
        <div class="label">Interaction vs. Concat</div>
        <div class="desc">Does elementwise multiplicative interaction ($v \odot t$) capture richer cross-modal relationships than simple linear feature concatenation ($[v, t]$)?</div>
      </div>
      <div class="highlight-stat-card">
        <div class="num">Q3</div>
        <div class="label">Parameter-Matched Control</div>
        <div class="desc">When holding trainable classifier capacity exactly equal (214,666 parameters), does the multiplicative product outperform an elementwise additive mean baseline?</div>
      </div>
    </div>
  </section>

    <h2>Amazon Berkeley Objects (ABO): Provenance, Filtering, and Class Support</h2>
    <p>Amazon Berkeley Objects (ABO) is a large-scale multimodal dataset introduced by Collins et al. (CVPR 2022). The full release contains 147,702 product listings and 398,212 catalog images. To ensure computational tractability while adhering to course depth requirements, our study uses the small-image package (longest edge bounded at 256 pixels) and the primary product metadata under the Creative Commons Attribution 4.0 International license (CC BY 4.0).</p>

    <h3>Metadata Audit &amp; Pair Ingestion Pipeline</h3>
    <p>A comprehensive metadata audit conducted on 11 November 2026 screened the raw listings catalog:</p>
    <ul>
      <li><strong>Initial Ingestion:</strong> Evaluated 19,616 Amazon.com listings. Exactly 19,542 listings possessed a non-empty <code>en_US</code> title, a valid single catalog category, and an indexed primary image reference (74 listings lacked an image match, a 0.38% omission rate).</li>
      <li><strong>Conflict Resolution:</strong> The retained listings mapped to 16,605 unique image IDs. Exactly 387 image IDs were associated with conflicting product type labels across duplicate listings and were discarded. For non-conflicting duplicate image IDs, the lexicographically smallest listing ID was retained.</li>
      <li><strong>Ten-Class Cohort:</strong> Restricting the curated pairs to ten balanced and visually distinctive e-commerce categories yielded <strong>7,221 verified candidate image–title pairs</strong>.</li>

  <section id="leakage" class="study-section">
    <span class="eyebrow">03 / LEAKAGE DEFENSE &amp; SPLIT PROTOCOL</span>
    <h2>Product-Group Disjoint Partitioning: Zero Entity Leakage</h2>
    <p>In e-commerce datasets, multiple listings frequently share the same underlying product entity (e.g., color variants, size bundles, or identical stock photographs reused across regional sellers). Randomly partitioning individual rows would place near-identical images and titles into both training and test sets, inflating evaluation scores.</p>

    <p>To eliminate cross-partition contamination, we enforce <strong>Product-Group Disjoint Partitioning using split seed 36</strong>:</p>
    <ul>
      <li><strong>Partition Unit (<code>group_id</code>):</strong> Product groupings are constructed by auditing perceptual image hashes, exact duplicate images, and metadata brand/model codes. All listings belonging to the same product variant share a single <code>group_id</code>.</li>
      <li><strong>Disjoint Invariant:</strong> No product group appears in more than one partition ($\text{Train} \cap \text{Val} = \emptyset$, $\text{Train} \cap \text{Test} = \emptyset$, $\text{Val} \cap \text{Test} = \emptyset$).</li>
      <li><strong>Class Support Guarantee:</strong> The deterministic greedy allocation targets a 70/15/15 ratio while guaranteeing that all 10 classes are populated in train, validation, and test sets.</li>
    </ul>

  <section id="methodology" class="study-section">
    <span class="eyebrow">04 / METHODOLOGY &amp; MODALITY ENCODERS</span>
    <h2>Modality-Specific Encoders, Preprocessing &amp; Title Masking</h2>
    <p>Following modern multimodal benchmarking standards, feature extraction leverages high-quality pretrained frozen backbones, isolating the investigation to <strong>fusion operations, cross-modal interaction, and representation alignment</strong>.</p>

    <div class="study-two-col">
      <div>
        <h3>1. Visual Modality Encoder: ResNet-18</h3>
        <ul>
          <li><strong>Architecture:</strong> Deep Residual Network with 18 layers (He et al., 2016), loaded from <code>torchvision.models.resnet18(weights=ResNet18_Weights.IMAGENET1K_V1)</code>.</li>
          <li><strong>Preprocessing:</strong> EXIF orientation correction, RGB conversion, aspect-ratio-preserving resize to $256 \text{ px}$ on the shortest edge, center crop to $224 \times 224$, and ImageNet channel standardization.</li>
          <li><strong>Representation:</strong> Global average pooling exports a fixed <strong>512-dimensional feature vector</strong> $x_{\text{img}} \in \mathbb{R}^{512}$.</li>
          <li><strong>Freezing:</strong> All convolutional weights remain 100% frozen; zero gradient backpropagation into the backbone.</li>
        </ul>
      </div>
      <div>
        <h3>2. Textual Modality Encoder: DistilBERT</h3>
        <ul>
          <li><strong>Architecture:</strong> DistilBERT Transformer (Sanh et al., 2019), loaded from HuggingFace <code>distilbert-base-uncased</code>.</li>
          <li><strong>Preprocessing &amp; Tokenization:</strong> Title string normalization, lowercase conversion, and WordPiece tokenization capped at a maximum sequence length of <strong>64 tokens</strong>.</li>
          <li><strong>Title Masking Protocol:</strong> Explicit class name strings (e.g., <em>"chair"</em>, <em>"shoes"</em>, <em>"rug"</em>, <em>"table"</em>) are replaced with <code>[MASK]</code> tokens across all splits to force models to infer semantic concepts rather than relying on trivial keyword matches.</li>
          <li><strong>Representation:</strong> The 768-dimensional hidden state of the first special token (<code>[CLS]</code>) is extracted: $x_{\text{txt}} \in \mathbb{R}^{768}$.</li>
          <li><strong>Freezing:</strong> DistilBERT transformer layers remain 100% frozen.</li>
        </ul>
      </div>
    </div>

    <h3>Trainable Projection Layers &amp; Shared Latent Space</h3>
    <p>To align the heterogeneous feature spaces ($512\text{D}$ image vs. $768\text{D}$ text) prior to fusion, independent linear projection layers map both modalities into a shared $128\text{D}$ latent space with ReLU non-linearities:</p>
    $$v = \operatorname{ReLU}(W_v x_{\text{img}} + b_v) \in \mathbb{R}^{128}, \quad W_v \in \mathbb{R}^{128 \times 512}$$
    $$t = \operatorname{ReLU}(W_t x_{\text{txt}} + b_t) \in \mathbb{R}^{128}, \quad W_t \in \mathbb{R}^{128 \times 768}$$
  </section>

  <section id="compute" class="study-section">
    <span class="eyebrow">08 / COMPUTE &amp; STORAGE BUDGET</span>
    <h2>Hardware Feasibility and Efficiency Analysis</h2>
    <p>Because feature vectors are pre-computed using frozen backbones and persisted to disk, the head training phase is exceptionally fast and computationally lightweight:</p>
    <ul>
      <li><strong>Storage Footprint:</strong>
        <ul>
          <li>Listing JSON archive: ~83 MiB; Small image archive: ~3 GB.</li>
          <li>Extracted feature caches: ResNet-18 image cache is ~14.8 MiB; DistilBERT text cache is ~22.2 MiB (total cache size ~37 MiB for 7,221 samples in FP32).</li>
        </ul>
      </li>
      <li><strong>Compute &amp; Training Budget:</strong>
        <ul>
          <li>With ~5,055 training pairs and batch size 128, each epoch requires only ~40 optimizer steps.</li>
          <li>Training an entire 8-epoch head requires ~320 optimizer steps (~1,600 steps per seed across all five models).</li>
          <li>Each head trains in under 15 seconds on CPU and under 2 seconds on GPU, enabling extensive multi-seed stability verification at near-zero carbon footprint.</li>
        </ul>
      </li>
    </ul>
  </section>
